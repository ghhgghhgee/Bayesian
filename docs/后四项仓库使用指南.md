## 4. 正式扫描和组长复跑

先把个人实验分支创建好，例如 `git switch -c experiment/full-scan-yourname`。正式运行前记录 `git rev-parse HEAD`，并确保代码和配置修改均已提交；两轮期间不要改代码、配置、说明文档或拉取新提交，源码哈希会变化。

```powershell
.\.venv\Scripts\python.exe main.py run --config configs/team_members/paper.json --registry algorithms_baselines_member.json --out results/team_paper_a --data-dir data/team_paper_a
.\.venv\Scripts\python.exe main.py plot results/team_paper_a
```

规模为 N=100、59 个去重工况、每点 300 次、六个成员算法，共 106,200 次调用。扫描一：K=3，M=1..30；扫描二：M=30，K=1..30；(30,3) 共用。耗时及数据大小取决于机器，不要用 smoke 完成时间直接当作保证。

检查 `manifest.json` 的 `complete=true`、`errors=0`；`summary.csv` 应有 354 行数据（59×6），`trials.csv` 应有 106,200 行数据。命令正常退出不代表算法没有异常，要同时看 errors。遇到异常保留日志、manifest 和失败样本编号，交给组长，不得删掉失败样本再算成功率。

目前 run 不支持断点续跑；中断目录不能当作完整扫描。与组长协调新输出目录再重跑。电脑应保持唤醒，并留足磁盘空间，尤其完整迭代轨迹。

组长使用同一版本独立运行到 `results/team_paper_b`、`data/team_paper_b`，再执行：

```powershell
.\.venv\Scripts\python.exe main.py compare results/team_paper_a results/team_paper_b --report results/team_paper_compare.json
```

标准 compare 包括环境版本检查；不同 Python/NumPy/平台会使该项失败，不可删掉检查后宣称“全通过”。跨机器时应分别报告环境差异及数值差异。耗时本来就不要求一致。

## 5. 每个结果文件怎么用

| 文件 | 用途与注意点 |
|---|---|
| manifest.json | 配置、算法入口及参数、源码哈希、commit、环境、完成状态、错误数和输出哈希；必须随结果交付 |
| summary.csv | 每个工况每个算法的成功数、成功率、平均 MSE/NMSE、平均迭代数、中位耗时；报告表格优先使用 |
| trials.csv | 逐样本指标、输入哈希、停止状态、耗时、错误记录；用于追查异常和统计 |
| estimates.npz | 完整最终估计；Git 默认忽略，独立指标审计需要它 |
| histories.npz | 每轮真实估计及累计耗时；Git 默认忽略，重新画收敛图需要它 |
| success_rate.png | 成功率随 M/K 的两个面板；完整配置才有完整 Fig.3 扫描，smoke 图不能冒充 |
| convergence.png | M=30,K=3、trial=0 的单样本时间/迭代曲线；不是 300 次平均结果 |

`main.py plot` 需要本地 histories.npz。GitHub 下载的历史结果通常只有 CSV/图/manifest，缺少 NPZ 时不能直接重画；向实验同学取完整输出或按记录版本重跑。

## 7. 第 6–8 项统一采用的指标和参数

| 名称 | 定义或本次约定 |
|---|---|
| 成功率 | 相对 L2 误差严格小于 1e-3 的次数 / 总试验次数；异常不能从分母删除 |
| 普通 MSE | ||x_hat−x||² / N |
| NMSE | ||x_hat−x||² / ||x||² |
| 论文 MSE(dB) | 10 log10(NMSE)，等价于 20 log10(相对 L2 误差) |
| 数据 | A 为标准正态、不做列归一化；无噪声；均匀随机支撑、标准正态非零幅度是本项目明确采用的生成约定 |
| NP0/NP1 | 通用停止阈值 1e-3、最多 300 次；具体截断等参数见注册表 |
| 成员 SBL/FOCUSS/IRLS | 注册表用 convergence_tol=1e-8 覆盖配置的通用 tol；最多 300 次 |
| 成员 IRLS | p=0.5，平滑项 x²+epsilon；epsilon 从 1 到 1e-8，满足变化条件后乘 0.1 |
| 成员 FOCUSS | p=0 的基础版本，为额外基线 |
| BP | 等式约束 L1 最小化，SciPy HiGHS；LP 内部迭代不受框架 max_iter=300 的含义约束 |

**不要混淆**：converged=true 是算法满足停止条件，success=true 才表示恢复了真实信号；测量残差很小也不等于恢复成功。`10log10(mean NMSE)` 与 `mean(10log10 NMSE)` 不是同一统计量，报告必须写清。`median_seconds` 是调用耗时中位数，history 时间是算法内部累计时间，两者不要混称。

成员基线是按文献实现的本地版本，不是原论文作者软件。成员 IRLS 的参数、平滑策略与旧参考版不同，也不能直接命名为论文 IRLS₀ 并声称精确复现。图例建议写“平滑 IRLS（p=0.5，成员实现）”，报告披露参数选择。停止阈值不同会影响迭代数和耗时，不能把性能差异全归因于算法本身。

## 9. 怎么提交自己的文件

每人创建自己的分支，例如报告同学：

```powershell
git switch -c report/yourname
git add deliverables/report deliverables/figures
git diff --cached --stat
git commit -m "docs: add report and figure sources"
git push -u origin report/yourname
```

实验同学只选择本人的输出和脚本暂存，例如：

```powershell
git add results/team_paper_a scripts/你的绘图脚本.py deliverables/figures
git diff --cached --stat
```

把占位文件名换成实际路径；不要执行不存在的路径。Git 自动忽略大 NPZ、data 和环境。完整 NPZ 请通过组长约定的文件共享方式交付，记录文件名、SHA256 和取用位置；不能因为 GitHub 上有 PNG 就删除本地完整输出。用 `Get-FileHash 文件路径 -Algorithm SHA256` 计算哈希。

然后在 GitHub 创建从个人分支到 main 的 Pull Request，把链接交给组长。`git add` 只是暂存，必须 commit 和 push 后网页才有新文件。不要强推 main，不覆盖别人目录，不提交登录凭据或虚拟环境。

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| KeyError: SBL_MEMBER 等 | 检查 --registry 是否遗漏；不要改回旧算法名字来掩盖问题 |
| No module named algorithms.baselines_member | 检查源码位置和仓库版本，命令应从仓库根目录执行 |
| 输出目录已存在 | 换新的目录名；不删除他人的结果 |
| compare 的 same_source=false | 两轮中间改过源码/配置/文档；固定版本后重新建立一对实验 |
| plot 找不到 histories.npz | 获取完整输出或重跑；Git 默认不保存该文件 |
| 只有显示窗口，没有结果文件 | `scripts.baselines_member_display` 是内存展示入口；正式实验使用 main.py run |
| 成功率与旧结果不同 | 先检查输入哈希、算法入口、参数和版本，不为凑数字改种子或删除失败样本 |

最新验收状态看 `docs/交付与验收.md`；基线公式、来源和具体数值约定看 `docs/baselines_member.md`。本指南交付给组长，由组长分享给成员，未代发消息。
