注册条目：`{"entrypoint":"team.np1_member_a:solve","owner":"成员姓名/编号","params":{}}`。在实验 JSON 的 algorithms 列表中加入该名字。params 不要重复 seed/max_iter/tol。MATLAB 代码需由成员提供 Python 适配器或统一导出的估计/轨迹后单独编写导入工具，当前框架不会自动执行 .m 文件。

验收步骤：

1. 作者提交模块、依赖、公式/来源、参数、短样例、Git commit。
2. 另一名成员从干净检出创建环境，先跑单元测试，再执行 reproduce.ps1。记录操作者及机器。
3. 检查两次 compare 全通过；再核对 success_rate 与普通 MSE、异常数和停止状态。确定性复跑通过不代表算法数学正确。
4. 核心实现组逐条核对式 (10)–(15)，基线组核对采用版本。必要时与参考实现对同一 A/y 比较，但不同算法/数值方案不要求逐位一致。
5. 运行 paper.json 两次，绘图组从 summary.csv 和 histories.npz 生成正式 Fig.3/4。说明未公开参数及偏差。
6. 在交叉验收表填写真实结果，不用“组长参考实现通过”替代“组员代码通过”。

复跑比较会忽略墙钟时间，但严格核对配置、源码/入口、输入数据指纹、逐次指标，并以 rtol=1e-10、atol=1e-12 比较估计与轨迹。注册代码本身的源码 SHA256 也进入 manifest；成员的辅助模块应放在本仓库，以进入统一源码清单。
